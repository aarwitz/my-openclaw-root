# AutoTrade Handoff — 2026-07-30

This supersedes `HANDOFF-20260729.md`. The system is safer and its loops are
structurally healthy, but it is **not ready to scale or promote beyond internal
paper trading** because the strategy currently has no validated edge.

## Material defects found and repaired

1. **Mechanism validation was not trustworthy.** The library contained
   in-sample/reused/cross-sectional artifacts presented as predictive or causal.
   The robust replay killed every current mechanism. Integration now admits only
   held-out, multiple-testing-surviving results and cannot reset live history.

2. **The world-model ledger had 15 foreign-key breaks.** An old reset path had
   deleted 14 referenced mechanism parents. They were reconstructed only for
   historical referential integrity and remain permanently deprecated.

3. **Five forecasts were graded before maturity.** AMD/PGR/TSM/CHTR/PKX and 14
   derived mechanism observations were reopened/removed. The exact
   trading-session resolver later matured AMD legitimately as incorrect
   (-16.978% return, -14.84% excess). Backlog is now 0 matured unresolved.

4. **Closed-trade attribution used stale position marks.** It now reconstructs
   returns from actual entry/exit fills and accepts nanosecond timestamps.
   Coverage is 49/49; the corrected result remains negative.

5. **The big-story metric leaked the future.** It counted theses authored up to
   two days after a move and arbitrarily old notes, creating the false 45/45
   coverage headline. It now accepts only theses from the 10 days strictly
   before an event and prefers the pre-event forecast median for direction.

6. **The GUI had a live external-broker fallback.** The separate
   `lidi-solutions` live API is now internal-KV-only, checks provenance and
   numeric account state, returns the browser's correct position/order keys,
   and fails closed with 503 when the snapshot is absent or invalid. The
   snapshot exporter can no longer switch broker backends or read broker
   credentials.

7. **Incomplete daily bars leaked into close-derived logic.** Same-day bars now
   remain incomplete until the actual exchange close (including early closes);
   partial price rows fail integrity checks. The July 30 “47 incomplete rows”
   alert was also corrected: 0 were price-derived.

8. **The July 24 learning debrief was missing.** It was backfilled using only
   bars knowable on July 24, and debrief coverage is complete for the last five
   trading days.

9. **Idle-cash drag fabricated a dollar loss without edge.** With zero robust
   ideas, idle cash is now classified as optionality, not missed opportunity.

10. **Safety tests had rotted.** The stop test patched a deleted single-symbol
    quote function and `_db` imports depended on test order. Bulk quote behavior
    is now tested, and Developer/trading helpers use a unique module name.

11. **Telegram narration produced duplicate receipts.** Every enabled
    Telegram-authoring cron now sends at most one useful message, uses delivery
    mode `none`, and returns exactly `SILENT_SUCCESS`. A fleet-wide regression
    test enforces the contract.

12. **Legacy provider/topology code was dangerous.** Active external-broker
    branches and two one-shot rewrite scripts capable of restoring obsolete
    topology were removed. Historical incident text remains historical.

13. **The GUI's execution/proposal cards reported stale state as live.** Three
    already-satisfied deprecation proposals were superseded with audits, taking
    “awaiting Aaron” from 3 to 0. Filled orders are no longer counted as
    “working,” and open positions use an explicit database count rather than a
    50-row mixed history slice. Verified payload: 0 working orders / 38 open
    positions.

14. **Backup health selected the wrong file.** Mixed daily and `PRE-*` backup
    names were sorted lexically, causing a current backup to be reported as
    27.7 hours old. Freshness now uses file modification time; final read-back
    is current locally. The Mac is explicitly iOS-build-only and no longer
    participates in internal-paper backup health.

15. **Runtime publishing dirtied the website source tree every ten minutes.**
    Trader passes and the KV publisher rewrote tracked `data.json` and chat
    files in `lidi-solutions`, forcing a provenance exemption and recreating
    the exact dirty-tree condition that blocked agent launches. Runtime output
    now lives under `state/trader-intel-snapshot/`, is written atomically, and
    never touches the website checkout. The provenance exemption is removed.

16. **The GUI could make mixed-age account state look fresh.** The JS overlay
    accepted an old Python base and stamped the combined result with the current
    time. It now rejects a missing, future-dated, or older-than-30-minute base.
    `/api/trader-live` independently rejects stale, inconsistent, or
    wrong-provenance KV state and strips raw account identifiers.

17. **The static GUI fallback ignored intraday equity and surfaced weakly
    sourced ideas first.** The hero now combines daily/intraday ledger series
    and displays current broker equity; research cards prioritize ideas with
    attached evidence. Topology drift was corrected to v5 across code,
    fixtures, and docs.

## Remaining blockers

1. **No validated edge.** This is the main blocker. Do not reactivate mechanisms,
   increase exposure, or convert idle cash into a target until a genuinely
   held-out replay survives the same promotion bar and forward paper results
   become positive.

2. **Forward evidence does not exist yet.** The locked shadow holdout begins
   2026-08-03 and requires at least 60 sessions through 2026-10-30 without
   tuning on its outcomes. Historical development data is contaminated by
   iteration and cannot prove production edge.

3. **The production KV snapshot needs one explicit data-egress approval.** Code
   deployment is authorized and complete/in progress, but the platform blocked
   uploading the newly sanitized live paper snapshot to Cloudflare without an
   explicit user instruction to send that data. Until refreshed, the hardened
   live endpoint will reject the old inconsistent KV snapshot rather than leak
   or present it.

## Recommended next sequence

1. Explicitly approve uploading the sanitized internal-paper snapshot to the
   existing Cloudflare `TRADER_DATA` KV namespace, then verify
   `/api/trader-live` end to end.
2. Keep new-risk quarantine in force. Continue grading existing predictions and
   managing existing paper positions only.
3. Rebuild the research program around point-in-time theme/universe coverage and
   strict outer-loop validation. A mechanism may return only after:
   - clustered, cost-net, multiple-testing-corrected held-out significance;
   - adequate ticker and date breadth;
   - no reused/cross-sectional artifact as the promotion source;
   - a second untouched cohort or forward-paper confirmation;
   - positive selection alpha and monotonic calibration, not merely hit rate.
4. Treat Telegram as an alert/narration surface, never evidence. Every healthy
   claim must link back to a deterministic metric with point-in-time semantics.
